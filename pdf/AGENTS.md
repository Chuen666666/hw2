# AGENTS.md

## Scope

These instructions apply to the `pdf/` directory and supplement the repository-level `AGENTS.md`.

## Directory purpose

This directory is runtime storage for generated registration PDFs. `.gitkeep` preserves the otherwise empty directory in Git; actual registration PDFs are generated by `submit.php` and are not source files.

## Security and data handling

- Treat every generated PDF and its URL as sensitive registration data.
- Never commit, attach, publish, or inspect real registration PDFs unless the user explicitly requests an authorized task involving them.
- Keep filenames unpredictable and generated with a cryptographically secure random value. Never derive a filename from a student ID, name, email address, phone number, or another predictable identifier.
- The QR Code must continue pointing to the corresponding random PDF URL rather than embedding PDF data.
- Do not add directory indexes or another listing mechanism that exposes generated filenames.
- Do not rename, move, overwrite, or delete generated PDFs without first identifying the exact files in scope and obtaining authorization when user data could be affected.
- Keep `.gitkeep` when cleaning generated output so deployments still create the expected directory structure.

## Deployment and verification

- The web-server account must be able to write to this directory in production.
- Avoid granting broader permissions than the deployment environment requires. Do not copy the current blanket `chmod 777` pattern into new scripts without explicit justification.
- After changing PDF storage behavior, verify random filename generation, filesystem permissions, generated link routing, QR Code resolution, both deployment URLs, and that generated PDFs remain outside version control.
